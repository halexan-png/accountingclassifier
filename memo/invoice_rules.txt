How invoices get matched to a row

Every row either has a direct link to its invoice, or it doesn't.

If a row has a link, that link is used. The system never looks at the
description text for that row, even if the link turns out to be broken or
blocked - a broken link just means the invoice is marked "not read," it does
not fall back to searching the description.

If a row has no link, the system searches the description text for an
invoice number instead. It checks the main description first, and only
checks the additional description if the main one doesn't have a usable
number.

To be found, the invoice number must be written one of these ways, listed
from most to least reliable:
- With "INV" written right next to the number, with a space, #, -, ., or :
  in between (e.g. INV#84512, INV-84512, INV 84512). This is checked first
  and is the recommended way to write it.
- As the very first thing in the description, followed by at least two
  spaces before the rest of the text (e.g. "84512  Legal fees - Project
  Alpha").
- As a standalone number sitting next to an ordinary word, with nothing
  marking it as an invoice number. This still works but is the least
  reliable, so don't rely on it on purpose.

Rules that apply no matter which way it's written:
- It must contain at least one digit - a word made only of letters is never
  picked up.
- It must not look like a date (e.g. 3/14/24 is always ignored).
- It must be at least 4 characters long if written with "INV" in front, or
  at least 5 characters long if written either of the other two ways.
  Anything shorter is treated the same as if nothing was written at all -
  it will not be looked up, and the row will show as "invoice not read."
- The description field only holds 40 characters total. If the invoice
  number is written right at the end of a full field, the system can't
  always tell if part of it got cut off, so it's safest to put the invoice
  number at the very front of the description, and move any extra
  description text to the additional description field if space is tight.

Whatever number is written in the description has to match the invoice's
file name once spacing, punctuation, and case are ignored - e.g. writing
INV-84512 in the description will match a file named 84512.pdf or
INV-84512.pdf.

Getting the file into the system: only PDF files are accepted, uploaded
either by dragging them in or by browsing to a folder. Each file has a
maximum size limit. A separate lookup file can optionally be added to help
tell apart two invoices that would otherwise share the same number, but it
isn't required - dropping in a correctly-named PDF is enough on its own. If
a number matches more than one file and there's nothing to tell them apart,
the invoice is left unread and flagged as unclear rather than guessed.
